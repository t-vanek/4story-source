## Complete Recover and OnTimer semantics

`TObjBase.cpp:1322` returns for no actual Map, OS_DEAD or HaveStopRecover. HP recovery runs only at MT_NORMAL and `DWORD now >= DWORD(hpTick + 3000)`. MP uses its own analogous deadline in every mode. Each branch only enters when current resource is below its actual maximum. It performs DWORD addition, then caps to maximum, and sets its local tick to now. It executes one gain per timer pass, with no catch-up loop. A zero rate still sets the change flag, advances the clock and emits HPMP; a full resource does none of those. An implementation may explicitly refuse unsupported wrapped-resource states before mutation, but must not silently replace source DWORD wrap with invented saturating addition.

If either branch entered, source sends one combined `CS_HPMP_ACK` per actual GetNeighbor recipient, after both HP/MP changes. Recover sends **no CHARSTAT** and no result/failure opcode. The local `bKeepChange` is initialized false and never assigned in this complete function; its monster-color branch is unreachable here. `HaveStopRecover` at4088 scans every actual maintained template row for SDT_STATUS/SDT_STATUS_STOPRECOVER48, independent of action kind. Unsupported effect state cannot be interpreted as proof that this flag is absent.

`TMapSvr.cpp:6055` accumulates elapsed scheduler time and queues SM_TIMER_REQ once after at least1000ms, resetting its accumulator rather than replaying missed seconds. The complete `OnSM_TIMER_REQ` (`SSHandler.cpp:48`) samples current global DWORD tick, requires an actual Map and calls OnTimer only for the main player at381; replica clocks do not advance via this loop. `CTPlayer::OnTimer` at955 calls CheckMaintainSkill → Recover → ResetAftermath, then tests `mode==MT_BATTLE && DWORD(lastAttack+5000)<now` and calls ChgMode(MT_NORMAL). The strict battle timeout occurs after HP recovery: a timed-out battle actor therefore recovers MP first and only becomes eligible for HP on a later pass. It also runs for a dead actor even though Recover returned early. Ordinary entitlements/item expiry/save and other later timer responsibilities remain distinct existing or open producers.

`ChgMode` at `TObjBase.cpp:295` requires actual Map, assigns mode and lastAttack=now, sets both recovery clocks to now+5000 **only for BATTLE**, and broadcasts CHGMODE. Thus first gain after battle entry is normally no earlier than now+8000, because Recover adds its3000 cadence. Changing to NORMAL, including Revival, does not reset recovery clocks; a post-revival gain may already be due. Repeated same-mode requests still perform these source assignments and emit the packet.

The source movement function (`OnCS_MOVE_REQ`, `CSHandler.cpp:439`) assigns `m_bAction=bAction` at578 before testing `m_bAction!=TA_SITDOWN && bAction==TA_SITDOWN`. That reset branch at581/582 is unreachable in this source. Do not implement an inferred intended sit-down reset or bonus from that contradictory condition. Recover itself does not read sitting/movement/action or multiply a sitting rate.

## Entry, replica, promotion and demotion clocks are local

`CTObjBase` constructor sets hpTick/mpTick0 and modeNORMAL; `CTPlayer` constructor sets lastAttack0. Successful fresh admission does not stop at those defaults. World ADDCHAR704 creates its connection ReadyFALSE at789. After DB load and route/CHARDATA exchange, `OnMW_CHARDATA_ACK:847` sends ENTERCHAR at981 to every not-ready connection, including the fresh primary. Actual Map `OnMW_ENTERCHAR_REQ:1447` reads mode at1489, then at1622/1623 sets both recovery clocks to local now+5000 before sending its identity ACK. That real descriptor receipt is the clock initialization boundary; neither an arbitrary SQL load nor client CONREADY is equivalent.

Full source handoff uses `OnMW_ENTERSVR_REQ:3072` → DM_ENTERMAPSVR_ACK3161 → saved transfer body converted to DM_LOADCHAR_ACK → common load4424. Neither the full body nor common parser carries/assigns PC mode or recovery/lastAttack clocks. `ClearMain:222` clears inventories/effects/quests/etc but leaves these local fields untouched. The target's existing replica retains its own mode/clocks from prior descriptor receipt; the demoted source also retains its local values. In `TWorldSvr.cpp:3839–3974`, OnCheckConnect with no newly needed connection goes directly to CheckMainCON, so existing ready targets need not receive a fresh mode descriptor before promotion. A target can legitimately retain an earlier normal mode even when the former main is now in battle; this is a source-local-state quirk, not grounds for inventing a transfer mode byte or rejecting handoff heuristically.

Native OnMWCharDataReq already serializes `s.cluster.mode`, NativeEnterChar reads it, and promotion intentionally merges `incoming.snapshot.cluster=replica.cluster`. Preserve that existing source-compatible mode boundary. Recovery clocks belong outside the optional full native payload because a partial replica has no payload and demotion clears it. Promotion must capture the latest existing target-local mode/clocks after outstanding operations drain, then explicitly retain them across the incoming full snapshot replacement. Do not rebase recovery clocks on every HydrateTransfer or graph recovery call, nor serialize them in RELEASEMAIN/core fingerprints/SQL.

The initial structural review identified that allowing a primary descriptor to update clocks during an awaited Ready timer/cast could lose that update when the older snapshot is stored. The final implementation instead admits a primary descriptor only in Loaded phase and holds BeginProjection; Ready repair already uses the separate truthful ENTERCHAR_ACK and cannot write these clocks. A busy Loaded projection closes rather than publishing an unfenced update. This bound fits the actual current router: world_client.cpp awaits each m_on_packet callback serially, so the Loaded MW_SOULMATE projection completes before a later descriptor; client CONREADY requires Admitted and native periodic gameplay requires Ready. No legitimate concurrent Loaded gameplay producer was found in this source review. Replica LoadReplica rechecks the complete identity tuple, role and Pending phase after its SQL await before publishing. This establishes the reviewed source/API bound, not an executed race result.
