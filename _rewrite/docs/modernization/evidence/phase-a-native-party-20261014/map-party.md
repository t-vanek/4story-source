## Native authority and lifecycle

`IPlayerService::AuthorizeParty` is an explicit fail-closed API; only `PostgreSQLMapService` implements native authority. Its pooled read transaction takes the World owner fence before the Map owner and account/claim locks, then verifies the live local and primary Map advisory locks, exact local owner/generation/session key, primary authority epoch or replica-to-primary token/connection/epoch relation, current unlocked account login, nondeleted character and lossless configured wire-name bytes. The captured local authority epoch is also checked around suspension. Replica authorization does not accept a stale primary-owner row after its advisory connection dies. No party SQL writes, migration, ownership claim fabrication or substitute adapter success were added.

`BeginPartyProjection` excludes admission/checkpoint/gameplay/transfer/close operations and supports loaded/admitted/ready primaries plus ready replicas. Current connection, key, role, authority epoch, open socket and registered World link are checked after database suspension. The World reader still awaits every frame handler, so JOIN/DEL/ATTR retain source ordering. Membership remains in `CharacterClusterState`, including across the existing transfer runtime; it is not added to the source transfer DTO.

The Map only commits SQL `ready` in `CS_CONREADY_REQ`; source has no World Ready ACK. After that actual commit and local Ready transition, the native primary's `RefreshReadyParty` sends the existing `MW_PARTYMANSTAT_ACK` with actual supported current statistics, level and cached effective party id, including zero. Its read-only authority rechecks the exact current ready actor; no placeholder stats or new opcode/DTO field are introduced. World uses that authorized status frame to refresh actual current registry PARTYATTR (including actual partyless zero) before validating the supplied cached party id for ordinary status fanout. This repairs membership transitions that were correctly rejected while the actor was TransferOut/In. Unsupported current statistics leave this refresh explicitly OPEN.

Invitation action blocking reads the actual hydrated maintained collection and the published source template data: dead, any TRANS3, or STATUS6 with BLOCK3/HOLD8. Protection comes from current normalized SQL bit2 in the same read transaction. Expired entries still present in the live collection are handled like source `IsActionBlock`; invitation handling does not run simulation or grant/erase effects.

Successful ADD/JOIN vitals also require the verified current native `payload.statistics`. Unsupported maintained/stat branches cannot manufacture a roster from fallback maxima. A local ADD is dropped before creating a World invitation; an exact currently authorized invite target/CS JOIN instead returns the original terminal BUSY shape with four zero absence fields. World's non-YES branch consumes the pending invitation without importing those fields as accepted member stats.

Native HPMP producers in `handlers/skill.cpp`, `maintained_effect.cpp`, `inventory.cpp`, and `quest.cpp` publish MANSTAT once at the own-PC enqueue using actual packet bars. Neighbor HPMP does not publish another actor's status. `quest.cpp` also covers the native periodic output path. The previous item-use-only raw MANSTAT producer was replaced by that common output coupling. The source independent level-up MANSTAT is emitted in `postgresql_map_progression.cpp` with its exact intermediate level and bars; its later HPMP remains a separate source trigger. Inventory/level party dependencies still have their existing fail-closed guards.

## Explicit modernization differences

- Complete body/tail parsing, NUL rejection and enum ranges 0..5/0..2 reject malformed packets. Original ADD/JOIN did not enforce obtain bounds. Empty lookup names still reach World's source error lookup; they are not substituted with a successful character.
- Unsupported native current vitals prevent successful party creation/join and use the refusal described above. This is a deliberate supported-capability boundary; original source had its full stat implementation.
- The post-Ready status trigger and World membership refresh are a deliberate modern lifecycle repair, not an original registration acknowledgment. Ordinary `PublishPartyVitals` still suppresses effective partyless/SOLO status fanout as source does; only the separately authorized Ready trigger can send that existing zero-party status shape.
- Original `SendCS_HPMP_ACK`/level-up emitted MANSTAT only when effective `GetPartyID()!=0`. The new Ready probe deliberately also emits effective PID0 with actual supported statistics; World interprets it as authorized refresh input, not party creation, a Ready success reply or an original source zero-party producer.
- World commits real transient membership before awaiting roster fanout. If a later exact actor/pair/current-peer check fails after a partial JOIN mutation, the joined target loses its party operation permit and enters normal `CloseChar` cleanup; a failed preflight that mutated nothing does not tear down the actor. No successful roster is synthesized from a partial fanout, and the join is never replayed.
- A stale/unavailable invite recipient is dropped instead of sending a zero-vital BUSY with no currently authorized actor. World invalidates the exact invitation on close/transfer. No automatic NOUSER notification on that invalidation is implemented or promised.
- The party projection wait is bounded at three seconds. Missing a membership transition closes the recipient through ordinary drain/save/release rather than retaining a usable stale party; it never forces claim deletion or replays a JOIN.
- Known frame overflow is logged/dropped before enqueue (Plain16 and client total strictly below65535); full source strings are not truncated. Actual World transport failure closes the sender, without resend on a replacement socket or invented success.
- Neighbor ATTR delivery requires the actual current native recipient claim; a recipient busy with its local checkpoint may miss that neighbor mark. Its own party transition remains serialized independently.
