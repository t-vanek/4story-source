## Signed value and unsigned Calculate semantics

`NetCode.h:1521–1528` defines INCREASE1, DECREASE2, MULTIPLY3, DIVIDE4, PRECENT5. Native `domain/skill_data.h` matches those values, including the original PRECENT spelling. Let V be checked signed GetValue, B the actual DWORD maximum, and U the source-defined conversion `uint32(V)`.

| Mode | Original operation and bounded interpretation |
| --- | --- |
| INCREASE1 | Final signed delta is V. A negative final result is outside positive CURE. |
| DECREASE2 | Final signed delta is -V. INT_MIN is refused before unary signed negation; a negative V can legitimately produce positive healing. |
| MULTIPLY3 | DWORD `B*U`, then DWORD subtraction of B. Require the product to fit DWORD and the projected total to be at least B. |
| DIVIDE4 | Source explicitly changes a signed divisor≤0 to1; then unsigned `B/divisor - B`. Require subtraction not to underflow. |
| PRECENT5 | DWORD `B*U` **before** promotion and double division by100.0; INT-truncate that total, then mixed INT−DWORD subtraction of B. Require nonwrapping product/subtraction and safe conversion. |

MULTIPLY/DIVIDE/percent are not signed algebra over an INT-cast maximum. Source DWORD and INT have equal rank/width; usual conversions produce unsigned32 multiplication/division/subtraction in those expressions. The generic native skill engine previously used signed expressions for some of them and had an unchecked fallback in Finish. That engine is not the oracle for this source contract.

Signed→DWORD conversion itself is defined and retained, including negative factors. It must not be conflated with arithmetic wrap. A source signed factor-1 converts to4294967295; with actual base1 the product fits DWORD. PRECENT then gives `int(4294967295/100.0)-1 =42949671`, a positive all-roll-safe delta. Rejecting every negative multiplier would discard that safe source case without a dependency reason. Conversely unsigned multiplication/subtraction wrap remains explicitly OPEN even if its eventual source bit pattern could look like a small positive INT.

The percent operation returns a **delta**, not a target resource or an additional percentage heal. Base1000/factor150 yields projected1500 and delta500. Its integer DWORD product must happen before the double division; `double(B)*V/100` changes source conversion/wrap semantics. A checked nonwrapped DWORD product is at most4294967295, so this percent total is at most42949672.95 before truncation; the explicit finite/INT guard still precedes the cast.

Base0 is a real actual maximum, not a fallback for missing stats. In unsigned combines it can produce exact0 even for negative V, but GetValue must first run, including all Calc2 guards. DIVIDE's ≤0→1 is the actual source branch, not a guessed divisor. For positive B and divisor>1, the quotient is below B, so this implementation refuses the source subtraction-wrap branch; it does not replace it with a0 heal.

## Safe final delta, variance and unknown modes

The new helper split makes `native_cure::SignedValue` preserve a safely representable signed INT before combining. It admits Calc0/1/3 through the existing integer expressions and Calc2 through its finite FLOAT/double/INT checks. A raw negative fraction such as-0.5 still truncates to0; a negative representable integer remains available for a legitimate DECREASE or source DWORD conversion. The positive guard is applied to the **final delta**, not prematurely to GetValue. Unknown Calc>3 explicitly throws rather than reaching the generic source default0.

`native_cure::Magnitude(row,skill,currentRank,actualMaximum)` evaluates the selected combine. Its uint64 multiplication can represent the product of any two DWORDs and is checked against UINT32_MAX before narrowing. Subtraction is performed only after projected>=base. INT_MIN is refused specifically where DECREASE would negate it, even though a widened native negation could otherwise manufacture a defined result absent from the source. Percent casts have explicit finite/INT representability checks before conversion. Unknown combines throw; no default0 is used to claim their implementation.

The final delta must be in0..floor(INT_MAX/15)=**143165576**. Only then can every source `delta*(rand()%16)` signed product and resulting row magnitude be represented. An intermediate GetValue may exceed that final bound if a legitimate combine reduces it. Each row, including a zero-valued row, retains its independent source variance draw when actually applied.

The existing Finish guard separately checks **the actual sampled row addition** against DWORD resource overflow. The all-roll guarantee above concerns signed variance, not a promise that all future resource additions were prevalidated at item acceptance. Resources/context can change before Finish. Rows accumulate before the source resource cap after the loop; they are not individually capped or recalculated against changing current bars. Product/subtraction/resource wrap, negative final effects, unsafe conversion/negation and unsupported modes remain unavailable. No result is saturated, clamped to a fake0, or used to invent successful offensive behavior.
