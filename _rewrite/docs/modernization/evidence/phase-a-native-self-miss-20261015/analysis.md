## Two distinct DEFEND packets and recipient scopes

`Server/TMapSvr/CSSender.cpp:1226` is the actual DEFEND sender. Its body without damage entries is **84 bytes**. It includes actual critical byte, hit byte, attack level, powers, actual countries, skill/rank, action flag, both positions and a zero damage-count tail.

For each nonempty own-PC target occurrence, source order is:

1. Update target last-attack clock. A MISS performs no cure arithmetic or cure random roll.
2. `CheckEternalBuff` (`TObjBase.cpp:2562`) removes existing PC maintained effects when MP is0 and their actual template has `bIsuse && !dwDuration`. Each removal has its own END, conditional maximum-change HPMP, and private CHARSTAT from `EraseMaintainSkill` at2621. Positive own-PC Defend does not invoke the other-actor/negative `EraseBuffByDefend` branch.
3. Send the original cure DEFEND84B with maintain0, duration0, **hit0/action0**, actual critical/rank/powers, own host/type and zero damage entries. Nonmaintained source `GetNeerPlayer` means neighboring cells plus64-unit radius.
4. Send its final HPMP only if the source `bHPMP` captured **before** eternal cleanup was true. A pure-marker MISS has no such resource change. Recomputing this condition from post-erase resources would duplicate erasure notifications.
5. Attempt ForceMaintain802. A missing template returns FALSE and sends no fabricated buff, but the original MISS remains a valid completed Defend.
6. After all targets, perform normal equipment-posture cleanup. Empty-target ordinary/loop/ACT completion reaches this cleanup without any hit test, MISS DEFEND or Avoid.

`ForceMaintain` is the complete `TObjBase.cpp:4397–4494`. It finds the actual chart, constructs rank1, calls MaintainSkill and PushMaintainSkill, then sends a separate maintained DEFEND to source `GetNeighbor` (3×3 cells, no64 radius). Its **wire host/type are0/0**, wire attack-level1, actual character level, zero powers/critical, select1/cancel0, NORMAL hit1/action1, skill802/rank1, actual duration and self positions. Its saved effect ownership remains actual self-PC host/attacker, stored hit/attack-level/attacker-level0. These stored/wire differences are intentional. ForceMaintain returning TRUE does not itself prove an effect was pushed or acknowledged by the client.

`Client/TClient/CSHandler.cpp:2806–3302`, complete `OnCS_DEFEND_ACK`, reads this layout. MISS produces the client's MISS-number presentation and skips non-MISS defend animation. `bSkillAct=0` avoids executing the cure's skill-function presentation. A following maintained802 packet independently creates or refreshes the skill-ID-keyed client maintained entry and its actual duration. Server duplicate instances do not imply duplicate client map entries; no invented client heal/reset packet belongs here.
