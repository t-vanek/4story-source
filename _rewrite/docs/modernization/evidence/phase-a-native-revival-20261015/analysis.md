## Baseline defect and bounded implementation contract

`Server/TMapSvrAsio/handlers/combat.cpp:455` accepts a request prefix without EOF/finite-position checks, mutates a dead actor's cache to full HP/MP and arbitrary coordinates, then sends revival/HPMP packets to the whole channel. A hydrated native PostgreSQL player can reach that same path without a durable transaction, exact Ready-primary claim, physical-cell owner proof or graph checkpoint. Source ordinary revival restores 30/40 percent and changes aftermath/effect state. The cache-only path must therefore be separated before native payloads can enter it; a native unsupported case must not fall back to the prototype.

The existing native `OnNativeQuestReq`/`PostgreSQLMapService::ChangeQuest` pipeline supplies a coherent transaction boundary: session gameplay/admission operation, current immutable snapshot, actor/World/Map/account/current-user/claim ownership, catalog verification, checkpoint/core/children validation, operational receipt, atomic effect/core/graph writes and post-commit publication. The existing migration045 quest operation can record another existing opcode; no new revival-specific success packet or migration is justified. The request and original packets must remain unchanged. Restrict this increment to real Ready primary, ordinary mode/map, known statistics/effects, no unsupported companion/recall/guild/local graph and a finite source-representable position within the same64-unit source cell and actual native physical owner. Cross-cell movement/visibility changes and special revival modes require their own complete contracts.

## Original request, state changes and client bytes

`Server/TMapSvr/CSHandler.cpp:1067` reads three FLOAT coordinates plus BYTE type (13 bytes); client `Client/TClient/CSSenderAll.cpp:23` sends this request to all Map sockets. Source first requires `m_pMAP`, sets WAKEUP/STAND, assigns Y and invokes the real `TMap::OnMove(x,z)`, then only the main player invokes `Revival`. The original request handler does not itself check dead state, finite coordinates, exact EOF or a two-value enum. `NetCode.h:2169` defines NPC0, GHOST1, HELP2. This CS handler maps NPC0 to AFTERMATH_ATONCE20 and every nonzero request to AFTERMATH_GHOST10 (`TMapType.h:59`). HELP12 belongs to the separate skill revival path. A native0/1-only request restriction must not be described as an original parser gate. Normal client NPC/ghost actions send current ghost coordinates (`TClientGM.cpp:837/869`), not a server-selected spawn warp.

`TPlayer.cpp:3610` performs the following original ordinary sequence:

1. Apply aftermath. If its step changes, send neighbor `CS_AFTERMATH_ACK` and owner `CS_CHARSTATINFO_ACK` before recalculating revival bars.
2. Recompute actual maxima; set WAKEUP/STAND and `ChgMode(MT_NORMAL)`. `TObjBase.cpp:295` updates the actual mode/attack clock and sends neighbor `CS_CHGMODE_ACK`.
3. NPC/at-once restores DWORD(maximum*0.3), ghost DWORD(maximum*0.4); HP is at least1, MP may remain0. HELP uses its actual supplied skill; NONE restores full bars. Tournament forces at-once while skipping aftermath; BOW selects NONE; BR includes separate team/spawn relocation. These branches are not interchangeable.
4. `RespawnCompanion` recreates actual companion state. Keep unsupported real companion/recall graphs outside the bounded path.
5. For each actual neighbor, send `CS_REVIVAL_ACK` then `CS_HPMP_ACK` (`TPlayer.cpp:3809`). Finally call `ForceMaintain(TREVIVAL_SKILL=800, self host/attacker, forced remaining0)` at3837.

Actual bodies: `CSSender.cpp:1404` REVIVAL is DWORD character plus3 FLOAT coordinates (16 bytes), with no result or bars; HPMP at1315 is DWORD object, BYTE type and4 DWORD max/current HP/MP (21 bytes), **no level byte**; AFTERMATH at5810 is DWORD character plus BYTE step (5 bytes). CHGMODE at1172 is DWORD object, BYTE object type and BYTE mode. `Client/TClient/CSHandler.cpp:2011` only changes a dead/ghost PC's presentation on REVIVAL; HPMP supplies the bars. AFTERMATH at17685 updates the actual actor field. Existing complete character-stat and DEFEND encoders must retain their original fields.

The source owner `SendCS_HPMP_ACK` also produces one `MW_PARTYMANSTAT_ACK` for the owner's effective nonzero party. Native committed-vitals publication should preserve that once-per-owner dependency and must not duplicate the source-level producer for each spectator. Source replicas also execute the request's WAKEUP/STAND/position prefix; primary-only native persistence does not by itself prove equivalent remote replica cache/presence/AI projection. That remote projection remains an explicit boundary until driven by an actual committed main outcome.

`TMap.cpp:1176` OnMove uses WORD coordinates divided by64. Crossing a cell may emit `MW_CHECKCONNECT`, leave/enter actual neighbor sets and invalidate an instance with no destination cell. A same-cell bounded revival avoids pretending to implement those operations. It still needs exact finite/range/physical-owner checks and post-commit presence position publication; it does not justify a whole-channel audience.

## Aftermath: actual persisted step and transient source clock

The complete fresh-load chain is essential. The player constructor begins with a zero runtime aftermath structure. `OnDM_LOADCHAR_REQ` then initializes CTBLChar query output defaults at `SSHandler.cpp:3313–3375`, including `query->m_bAftermath=0` at3365, **before** `query->Open()` at3377. `Server/TMapSvr/DBAccess.h` declares the BYTE field at145, selects actual `bAftermath` at192 and binds `COLUMN_ENTRY(m_bAftermath)` at235. Successful Open therefore loads the stored value. The DM reply serializes that loaded value at `SSHandler.cpp:3435`; the common load/transfer parser reads it at4516 and calls `SetAftermath(m_dwTick,bAftermath)` at5674. Thus constructor/query initialization → Open → COLUMN_ENTRY → DM body → common Set preserves the actual stored/transferred step and constructs a new local deadline. The isolated pre-Open zero assignment is **not** a successful-load override. Both owners were told this correction before implementation; no incorrect fresh-reset claim should survive.

`TPlayer.cpp:3444` SetAftermath returns immediately below level10. Otherwise it adds BYTE step, caps values above100 after the BYTE addition, and only on an actual change sets reuse increase FLOAT(step*0.5), stat decrease FLOAT(step*0.3) and deadline `tick + DWORD(27 + step*0.3)*1000` (truncate before multiplying). It clamps current HP/MP to the new maxima, then broadcasts AFTERMATH. A saturated unchanged step does not restart its timer.

`ResetAftermath` at3497 runs only when step is nonzero and **deadline < tick**. It computes BYTE decrement `1 + CalcItemAbility(ABILITY_AFTERMATH)`, subtracts into BYTE (including original underflow/wrap), recomputes both rates, and adds `DWORD(27+newStep*0.3)*1000` to the prior deadline. It applies one decrement per timer pass, not catch-up to zero. Neighbor order is AFTERMATH then HPMP; owner CHARSTAT follows. `TPlayer.cpp:957–959` calls CheckMaintainSkill, Recover, then ResetAftermath. `TObjBase.cpp:1780` derives the item decrement from actual equipped `GetMagicValue(MTYPE_AFTERMATH)` with the usual equipment/disguise/disweapon/disdefend rules.

No new persisted deadline is source-backed: core SQL and source transfer carry only the BYTE step. A native ephemeral clock should initialize from the actual step on fresh load/full transfer hydration and persist changed step through existing core/graph authority. It must not reset on each checkpoint. Existing native statistics reduce `min(step,100)*0.3`; if full BYTE-underflow decay is supported, that clamp does not reproduce source wrapped values and needs explicit correction or a bounded rejection before mutation. Inventory/stat changes must not silently lose the timer. Source writes `m_fReuseInc`, but a static search of Map and shared library source found no reader of that field; `TSkill.cpp:80–100` computes reuse from its existing supplied attack-speed/rate arguments. An additional aftermath reuse multiplier is therefore not justified merely by the field's name. The earlier handoff warning was corrected to distinguish the real stat reduction from this unused stored rate.
